# Type Checker Documentation

## Overview

The Type Checker is a comprehensive static analysis component that validates type correctness in the compiled program. It operates on the Abstract Syntax Tree (AST) generated by the parser and uses symbol table information from the Scope Analyzer.

## Features

### Supported Type Checking

1. **Variable Declarations**
   - Ensures variables are not declared with `void` type
   - Validates initializer expressions match variable types
   - Supports implicit type conversions (int ↔ float, int ↔ char ↔ bool)

2. **Function Declarations and Calls**
   - Validates parameter count matches
   - Checks parameter types are compatible
   - Ensures return types match function signatures
   - Verifies non-void functions have return statements

3. **Expression Type Checking**
   - **Arithmetic Operations** (`+`, `-`, `*`, `/`, `%`)
     - Requires numeric operands
     - Modulo (`%`) requires integral operands
   - **Logical Operations** (`&&`, `||`, `!`)
     - Requires boolean-compatible operands
   - **Bitwise Operations** (`&`, `|`, `^`, `~`)
     - Requires integral operands
   - **Shift Operations** (`<<`, `>>`)
     - Requires integer operands
   - **Comparison Operations** (`==`, `!=`, `<`, `>`, `<=`, `>=`)
     - Requires compatible types
   - **Ternary Operator** (`? :`)
     - Condition must be boolean-compatible
     - Both branches must have compatible types

4. **Array Type Checking**
   - Array size must be integer
   - Array indices must be integral
   - Array element types must match in initializers
   - Supports array-to-pointer decay

5. **Pointer Type Checking**
   - Validates pointer types in declarations and assignments
   - Dereference (`*`) requires pointer operand
   - Address-of (`&`) requires lvalue operand

6. **Control Flow Validation**
   - If/While/For/Do-While conditions must be boolean-compatible
   - Switch expressions must be integral
   - Case values must match switch type
   - Detects duplicate case values
   - Break/Continue only valid inside loops
   - Break also valid in switch statements

## Error Types

The type checker reports the following error categories:

### Variable and Declaration Errors
- **ErroneousVarDecl**: Invalid variable declaration
- **VoidVariableDeclaration**: Variable declared with void type

### Function Errors
- **FnCallParamCount**: Wrong number of arguments in function call
- **FnCallParamType**: Argument type doesn't match parameter type
- **ErroneousReturnType**: Return type doesn't match function signature
- **ReturnStmtNotFound**: Non-void function missing return statement
- **FunctionNotReturningValue**: Void function returns a value

### Expression Errors
- **ExpressionTypeMismatch**: Incompatible types in expression
- **EmptyExpression**: Empty or null expression
- **InvalidOperandTypes**: Invalid types for operator

### Boolean and Conditional Errors
- **ExpectedBooleanExpression**: Expected boolean in context requiring boolean
- **NonBooleanCondStmt**: Condition in if/while/for is not boolean-compatible
- **AttemptedBoolOpOnNonBools**: Logical operator on non-boolean types

### Numeric Operation Errors
- **AttemptedAddOpOnNonNumeric**: Arithmetic operator on non-numeric types
- **AttemptedBitOpOnNonNumeric**: Bitwise operator on non-integral types
- **AttemptedShiftOnNonInt**: Shift operator on non-integer types
- **AttemptedExponentiationOfNonNumeric**: Exponentiation on non-numeric types

### Array and Pointer Errors
- **ArrayIndexNotInteger**: Array index is not integral type
- **InvalidArraySize**: Array size is not valid
- **PointerTypeMismatch**: Incompatible pointer types
- **DereferenceNonPointer**: Attempt to dereference non-pointer
- **AddressOfNonLValue**: Address-of operator on non-lvalue

### Control Flow Errors
- **ErroneousBreak**: Break statement outside loop or switch
- **InvalidBreakContinue**: Continue statement outside loop
- **SwitchExpressionNotIntegral**: Switch expression is not integral
- **CaseValueNotConstant**: Case value is not constant
- **DuplicateCaseValue**: Duplicate case values in switch

### Ternary Operator Errors
- **InvalidTernaryTypes**: Incompatible types in ternary branches

### Other Errors
- **UndefinedType**: Reference to undefined type
- **AssignmentToNonLValue**: Assignment to non-lvalue
- **DivisionByZero**: Potential division by zero
- **ModuloByZero**: Potential modulo by zero

## Type System

### Base Types
- `int`: Integer type
- `float`: Floating-point type
- `char`: Character type
- `bool`: Boolean type
- `string`: String type
- `void`: Void type (for functions only)

### Derived Types
- **Pointers**: `int*`, `float**`, etc.
- **Arrays**: `int[]`, `float[10]`, etc.

### Type Compatibility

#### Implicit Conversions
1. **Numeric Conversions**
   - `int` ↔ `float` (with potential precision loss)

2. **Integral Conversions**
   - `int` ↔ `char` ↔ `bool`

3. **Array to Pointer Decay**
   - `int[10]` → `int*`

#### Type Promotion
- In mixed numeric operations, `int` promotes to `float`
- Result type is the "wider" of the two operands

## Usage

### Basic Usage

```cpp
#include "type_checker.h"

// After parsing and scope analysis
ScopeAnalyzer analyzer;
ScopeAnalysisResult scope_result = analyzer.analyze_scopes(ast);

// Perform type checking
TypeChecker type_checker(scope_result);
TypeCheckResult type_result = type_checker.check_types(ast);

// Check for errors
if (type_result.hasErrors()) {
    type_checker.print_type_errors();
}
```

### Getting Type Information

```cpp
// Get type of an expression node
std::optional<TypeInfo> type = type_checker.get_type(expr_node);

if (type.has_value()) {
    std::cout << "Type: " << type->toString() << std::endl;
}
```

## Implementation Details

### Type Information Structure

```cpp
struct TypeInfo {
    std::string base_type;      // Base type name
    int pointer_depth;          // 0 for regular, 1 for *, 2 for **, etc.
    bool is_array;              // True if array type
    int array_size;             // Array size (-1 if unknown)
    bool is_function;           // True if function type
    std::vector<TypeInfo> param_types;  // For function types
};
```

### Type Checking Context

The type checker maintains context information during traversal:
- Current function name and return type
- Loop depth (for break/continue validation)
- Switch statement status
- Whether function has return statement

### Design Principles

1. **Non-Invasive**: Does not modify the AST or existing code structures
2. **Comprehensive**: Handles all language constructs defined in the grammar
3. **Informative**: Provides detailed error messages with context
4. **Graceful**: Continues checking after encountering errors to report multiple issues

## Examples

### Valid Code

```c
function int add(int a, int b) {
    return a + b;
}

function float average(int x, int y) {
    return (x + y) / 2.0;  // int promotes to float
}

function void main() {
    int result = add(5, 10);
    float avg = average(10, 20);
    print result;
}
```

### Type Errors

```c
// Error: VoidVariableDeclaration
void x = 5;

// Error: FnCallParamCount
function int foo(int a) { return a; }
foo(1, 2);  // Too many arguments

// Error: NonBooleanCondStmt
if (5) { }  // Should use boolean

// Error: AttemptedBitOpOnNonNumeric
float x = 3.14;
float y = x & 2;  // Bitwise AND on float

// Error: ErroneousBreak
break;  // Outside loop or switch

// Error: ReturnStmtNotFound
function int missing() {
    int x = 5;
    // No return statement
}
```

## Integration

The type checker integrates seamlessly with the existing compiler pipeline:

1. **Lexer** → Tokenizes source code
2. **Parser** → Builds AST
3. **Scope Analyzer** → Builds symbol table and checks scope rules
4. **Type Checker** → Validates type correctness ← **Current Phase**
5. **Code Generation** → (Future phase)

## Testing

Test files are provided in the `tests/` directory to verify type checker functionality:

- `valid_codes`: Programs that should pass all checks
- `invalid_codes`: Programs with intentional type errors
- Error-specific test files for each error category

## Future Enhancements

Potential improvements for future versions:

1. **Enhanced Type Inference**: Infer types from context
2. **User-Defined Types**: Support for structs and classes
3. **Type Aliases**: Support for typedef
4. **Constant Folding**: Detect compile-time constant violations
5. **Warning System**: Non-fatal warnings for suspicious code
6. **Flow Analysis**: More sophisticated control flow analysis

## Notes

- The type checker assumes the AST is well-formed (parser succeeded)
- Scope errors should be resolved before type checking
- Source location information is simplified (would need token location tracking)
- Some error categories are not yet fully utilized but are included for completeness
